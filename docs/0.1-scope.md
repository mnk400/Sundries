# Sundries 0.1 — Beta Scope

The goal of 0.1 is the first build handed to coworkers. Not "feature complete" — **safe to point at a real
Markdown vault, and impossible to mistake a missing feature for a broken app.**

Distribution is build-it-yourself. No Developer ID account, so no signing or notarization work in this release.

Deferred by design: `TaskSourceAdapter` shape work is **0.2**. Obsidian Tasks metadata, FSEvents watching, and
launch-at-login are **0.3** — all three depend on decisions 0.2 makes, and would be built twice if pulled forward.

---

## 1. Blockers

### 1.1 Quit affordance
There is currently **no way to quit the app**. `LSUIElement = YES` means no Dock icon and no app menu, and the
`MenuBarExtra` is `.window` style with fully custom content whose footer holds only a gear
(`Views/MenuBarContentView.swift:128`). A tester's only exit is Activity Monitor.

Built as a footer overflow menu (`ellipsis.circle`) rather than a bare button, since Refresh wanted the same
place. The gear button it replaced moved into the menu as **Settings…**.

- [x] **Quit Sundries** — clicking the item always works, which is what clears the blocker
- [x] **Refresh** — §4.7, the only way to pick up an external edit until FSEvents lands in 0.3
- [x] **Settings…**
- [x] Loading spinner in the footer, so Refresh visibly does something
- [ ] Verify ⌘Q / ⌘R / ⌘, actually fire while the panel has focus. SwiftUI builds `Menu` content lazily, so
      item shortcuts may only be live while the menu is open. If they don't work, the fix is a hidden button
      group in the window's view hierarchy — the menu items themselves are unaffected either way.

### 1.2 In-panel error surfacing
`sourceIssue` renders only in Settings → Sources (`Views/SettingsView.swift:87`). A failed completion write
silently un-checks the row (`Store/TaskStore.swift:218-222`); a failed add silently restores the query text.
Both read as glitches.

- [x] `SourceIssueBar` in the panel, matching the undo bar's glass treatment
- [x] Distinguished by kind: `.folderUnresolvable` gets a **Settings…** action since that is where it is fixed;
      `.operationFailed` does not, because the retry lives where the user already is
- [x] Dismissible, and it takes the undo bar's slot rather than stacking — a problem outranks a confirmation,
      and the undo it covers is stale anyway
- [x] Self-clears: `TaskStore` already nils `sourceIssue` on the next successful read or write

Not addressed: `.operationFailed` messages are raw `error.localizedDescription`, so a Cocoa file error reads
like a Cocoa file error. Better per-source error copy is 0.2 work alongside the multi-source error model.

### 1.3 App icon — **done**
`Sundries.icon`, built in Icon Composer. Referenced explicitly in the project rather than through a
synchronized group, since it sits at the repo root, with `ASSETCATALOG_COMPILER_APPICON_NAME = Sundries` in both
configurations. Verified compiling to `Assets.car` + `Sundries.icns` with `CFBundleIconName` set.

**No menu-bar glyph** — the rendered count pill is the app's identity, by decision. Pill work is §6.

## 2. Tests — done

**44 tests in 5 suites**, Swift Testing, hosted by the app target. Gated the performance work in §3 — hoisting
regexes without a round-trip test is how a vault gets corrupted.

- [x] `SundriesTests` target added to `Sundries.xcodeproj`
- [x] `markdown-test-vault/` un-gitignored as contributor sample data. Tests deliberately build their own vault
      in a temp directory instead: a fixture that tests mutate stops being a fixture after one run.
- [x] Round-trip: parse → complete → re-serialize is byte-identical except the marker, across prose, headings,
      indented children, and a `- [ ]` lookalike inside a blockquote
- [x] `matchingLineIndex` fallback ladder — moved-line recovery, and refusing to guess when the task is gone
- [x] `TaskDraftParser`, including the §4.1 regressions and day-granularity
- [x] `TaskSection.contains` boundaries, via a new injectable `now:` parameter — it previously read `.now`
      internally and could not be tested at all
- [x] Line endings: `\n`, `\r\n`, mixed, no trailing newline, empty file
- [x] Missing-folder handling on all four operations, and the full `SourceIssue.from` mapping table

The project was also converted to **file system synchronized groups** (`objectVersion = 77`) partway through, so
new files in `Sundries/` and `SundriesTests/` are picked up without touching the project file.

## 3. Performance — done

`NSRegularExpression(pattern:)` was being constructed per line, three times over, plus a `DateFormatter` per
date parsed.

- [x] Hoisted all three regexes to `static let` on `MarkdownTaskParser`
- [x] Hoisted the `DateFormatter` to a single cached instance
- [x] Measured against a synthetic vault of 1,000 files / 50,000 lines / 17,000 tasks

**4.147s → 1.357s, a 3.1× speedup.** Debug build (`-Onone`), so the absolute numbers are inflated relative to
Release; the ratio is the meaningful part. Benchmark scaffolding was deliberately not committed — a wall-clock
assertion is too flaky for a real suite. Re-create it ad hoc if these paths change again.

Still outstanding as a *later* concern (not 0.1): every refresh re-reads every file with no mtime cache. At
1,000 files that is now ~1.4s of work on each panel open, which is survivable but not free. Revisit alongside
FSEvents in 0.3.

## 4. Bugs

### 4.1 `today's` / `tomorrow's` mangles titles — confirmed
`\btoday\b` matches inside `today's`, so **"Buy today's paper" becomes titled "Buy 's paper"** and silently
picks up a due date (`Services/TaskDraftParser.swift:20-36`). Also eats the word in "Plan the Today View
redesign." Anchor to a trailing token, or move to `NSDataDetector`.

### 4.2 Alternate checkbox states are invisible — **done**
`[/]`, `[-]`, `[>]` failed `checkboxPattern` and vanished entirely, which reads as data loss.

- [x] Widened the marker character class to `[^\]]`
- [x] Replaced `isCompleted: marker != " "` with `MarkdownTaskParser.isResolved(_:)`
- [x] Reopening restores the marker the task started with, so undo on a `[/]` no longer demotes it to `[ ]`

**Semantics chosen:** `x`, `X` and `-` are settled and stay out of the list — `-` is the widely used "cancelled"
convention, and surfacing every cancelled task as outstanding would be its own kind of wrong. Everything else,
including `/`, `>` and unknown markers, counts as open, because refusing to display a marker we don't recognize
is what made this look like data loss in the first place. Real source-defined status is 0.2 work.

Verified that widening the class did not start matching `- [[wiki links]]` or `- [x](markdown links)`.

### 4.3 Mixed line endings drop tasks — **done**
Choosing one line ending per file collapsed the lone-`\n` runs into a single unparseable line.

Replaced with `MarkdownDocument`, which splits into lines while remembering *each line's own* terminator, so a
mixed file round-trips exactly. Swift treats CRLF as a single `Character`, so all three endings fall out without
look-ahead. Re-benchmarked: 1.342s vs 1.357s — the character scan costs nothing over `components(separatedBy:)`.

### 4.4 Symlinked vault paths can collide task IDs — **done**
`relativePath(for:)` fell back to `lastPathComponent` when the prefix check failed, so two `Inbox.md` files in
different subfolders shared a relative path and therefore an identity — completing one flipped the other.

Now matches against both the chosen path and its symlink-resolved form, and the degenerate fallback returns the
full path rather than the file name: still unique, and any later write fails loudly instead of hitting the wrong
file.

### 4.5 Security scope may not survive relaunch — **verify first**
`MarkdownTaskSource.init:10` stores `rootURL.standardizedFileURL`, but `startAccessingSecurityScopedResource()`
is documented against the exact URL returned from bookmark resolution. If this is real, every tester configures a
folder, relaunches, and finds it disconnected — and will blame the bookmark code rather than URL identity.

### 4.6 Empty state promises an action that no-ops
"Press Return to add this as a new todo" (`Views/TaskListView.swift:25`), but `createTask()` returns early when
`selectedDestination` is nil (`Store/TaskStore.swift:185`). Dead end, no feedback.

### 4.7 Manual refresh
FSEvents is 0.3, so until then there is **no way to pick up an external edit** short of closing and reopening the
panel, and the menu-bar count never updates while the panel is closed. `refreshTasks()` already exists; this is a
menu item in the §1.1 footer menu plus a call.

### 4.8 Settings window activation — verify
Under `LSUIElement`, `openSettings()` commonly opens behind other windows without an explicit `NSApp.activate`.

### 4.9 A deleted folder read as an empty one — **done**
Found during interactive testing of §1.2. Deleting the configured folder mid-session produced **no error at
all** on the read path: `fetchTasks` returned 0 tasks and `fetchDestinations` returned 1 — its unconditionally
synthesized `Inbox.md`. So the list showed "No matching todos" for a vault that no longer existed, the composer
offered a destination pointing at nothing, and the only error appeared on write, naming `Inbox.md` rather than
the folder that had actually gone.

Same failure class as §4.2 and §4.3: a broken state rendering as a normal empty one.

No new error case was needed — `MarkdownSourceError.cannotReadFolder` already existed but was effectively dead,
thrown only when `FileManager.enumerator(at:)` returns nil, which does not happen for a deleted directory.

- [x] Renamed to `folderUnavailable` (covers moved, renamed, deleted, unmounted) and reworded
- [x] One reachability guard in `withFolderAccess`, which every read and write already funnels through — so
      `fetchTasks`, `fetchDestinations`, `createTask` and `setCompleted` are all covered by a single check
- [x] Added `SourceIssueRepresentable`, letting an error name its own `SourceIssue.Kind` so `TaskStore` never
      type-checks against a specific adapter's errors. Expired credentials in 0.2 are the same shape.
- [x] Renamed `SourceIssue.Kind.folderUnresolvable` → `.needsSetup`, since a source-agnostic type should not
      carry a Markdown-flavoured case name
- [x] Renamed the `SourceIssue.operationFailed(_:sourceID:)` factory to `.from(_:sourceID:)`, which no longer
      lies about the kind it produces

Two behaviours fall out for free: `reloadTasks` returns before assigning `tasks`, so the last-known list stays
on screen *with* an error bar instead of going blank; and `reloadDestinations` clears the selection, so Add
disables itself rather than letting you attempt a doomed write.

### 4.10 Dead code
`TaskStore.sampleTasks` (`Store/TaskStore.swift:326`) is unreferenced, which is why `#Preview` renders an empty
state. Wire it into the previews or delete it.

## 5. Date model — done

**Correction to the original finding.** This was written up as a visible bug — "a new task reads
*Today, 5:00 PM* and then silently becomes *Today*". That symptom does not actually occur.
`MarkdownTaskSource.task(from:)` passes `dueDateIncludesTime: false` explicitly on every path, including the
`TaskItem` returned from `createTask`, so no row ever rendered a time. The `true` default on
`TaskItem.init` was only ever reachable from the unused `sampleTasks`.

What was real is the underlying inconsistency: three conventions for one concept.
`TaskDraftParser` invented 17:00, `selectDueDate` used `startOfDay`, and the Markdown reader returned local
midnight — so the *same day* was three different `Date` values depending on how it was chosen. Harmless while
nothing compares dates for equality, and a trap the moment something does.

- [x] `TaskDraftParser` now produces `startOfDay`, matching `selectDueDate` and what Markdown can store
- [x] `TaskItem.dueDateIncludesTime` now defaults to `false` — sources carrying a real time of day opt in,
      rather than every future adapter inheriting a time nobody set
- [x] Kept the property. JIRA SLAs and SIM severity clocks are genuinely time-of-day, so deleting it here would
      only mean restoring it in 0.2.

Locked in by a round-trip test: a date drafted in the composer and the same date read back off disk are now the
same `Date`.

## 6. Menu-bar pill — done

- [x] **Zero state: deliberately unchanged.** The overdue segment can hide at zero precisely because the
      secondary segment anchors the pill — if both hid there would be nothing left to click, and "0 due today"
      is worth saying out loud rather than suppressing.
- [x] Respects Reduce Transparency: the capsule background goes from 0.14 to 0.28 opacity.
- [x] Fixed a latent blur: the renderer took its scale from `\.displayScale`, which in a `MenuBarExtra` label
      can still be 1.0 before there is a window to read it from, permanently rendering a soft pill on Retina.
      Now `NSScreen.main?.backingScaleFactor`.
- [x] **`isTemplate = false` kept, on purpose.** A template image is what would give free dimming on an
      inactive menu bar, but it flattens everything to the menu bar's tint — which would cost the red overdue
      segment, the one thing the pill exists to communicate. Not worth the trade at 0.1.

## Explicitly not in 0.1

Both open questions were resolved as **out of scope** — 0.1 stays a stability release.

- **Obsidian Tasks metadata stripping** → 0.3, as originally planned. Testers using the Tasks plugin will see
  raw metadata in titles (`Pay rent ⏫ 🔁 every month 🛫 2026-08-01`). Known and accepted; note it in the beta
  README so it isn't reported as a bug.
- **Search vs. capture.** Any keystroke opens the composer and pushes the list down
  (`MenuBarContentView.swift:22`), and Return *always* creates a task — so searching for an existing task and
  hitting Return duplicates it. A design change, not a bug fix, and too large for 0.1. Worth watching what
  testers actually hit here before redesigning it.

Also out: global hotkey · keyboard list navigation · edit / reschedule / delete · ⌘Z undo · Reveal in Finder ·
notarization · Sparkle · localization · incremental parse cache · Reminders adapter
